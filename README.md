# Provenance Guard

A backend service a creative-sharing platform can plug into to answer one
question about a piece of submitted text: **was this written by a person, or
generated by AI?** It classifies the text with two independent signals, scores
its confidence honestly (it says "uncertain" rather than guessing), surfaces a
plain-language transparency label to readers, and gives creators a way to appeal.

Design priority throughout: **a false positive (flagging a human's work as AI)
is worse than a false negative.** Thresholds, weights, and label wording are all
biased toward that asymmetry.

The full design spec and architecture diagrams live in
[planning.md](planning.md).

```
GROQ_API_KEY=your_key_here
```

to the stylometric signal alone and returns **uncertain** for everything (see

```bash
python app.py     # serves on http://127.0.0.1:5000
```

## API

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/submit` | Classify text. **Rate limited** (10/min; 100/day). |
| `POST` | `/appeal` | Contest a classification; sets status to `under_review`. |
| `GET`  | `/appeals` | Reviewer queue: everything under review + its appeal. |
| `GET`  | `/log` | Structured audit log (decisions + appeals). `?limit=N` optional. |
| `GET`  | `/health` | Liveness check. |

### `POST /submit`
```bash
curl -s -X POST http://localhost:5000/submit \
  -H "Content-Type: application/json" \
  -d '{"text": "The sun dipped below the horizon...", "creator_id": "test-user-1"}'
```
Returns `content_id`, `attribution` (verdict), `confidence`, `p_ai`, the
per-signal breakdown, and the transparency `label`. Save the `content_id` — you
need it to appeal.

## Detection signals (multi-signal pipeline)

Two **genuinely distinct** signals — one structural, one semantic. They fail in
different ways, which is exactly why combining them beats either alone.

### Signal 1 — Stylometric heuristics (structural, pure Python)
Measures the statistical *shape* of the writing, combining three sub-metrics into
one AI-likeness score in `[0,1]` (higher = more AI-like):
- **Sentence-length uniformity** — AI prose tends to be even; human writing is
  bursty (a three-word sentence next to a forty-word one).
- **Type-token ratio** (lexical diversity) — repetitive vocabulary reads AI-like.
- **Punctuation variety** — humans reach for dashes, semicolons, colons; AI is
  more regular.

*Blind spot:* it's fooled by register, not substance. Plain-but-human writing
(minimalist poetry) looks "AI-uniform"; sophisticated AI with rich vocabulary
looks "human." It is meaning-blind. (Implemented in [signals.py](signals.py).)

### Signal 2 — LLM classifier (semantic, Groq `llama-3.3-70b-versatile`)
Asks an LLM for a holistic judgment — coherence, voice, and the tells of
generated text — returning a probability in `[0,1]` plus a short rationale. It
reads *meaning*, which the stylometric signal cannot.

*Blind spot:* no LLM is a reliable detector (AI-text detection is unsolved). It
can be overconfident, biased against non-native or unusual-but-human styles, and
non-deterministic. (Implemented in [signals.py](signals.py).)

**Why the pair is strong:** the stylometric signal is deterministic and
content-blind; the LLM is content-aware but noisy. When they agree, we can be
genuinely confident. When they disagree, that disagreement is itself the signal —
we lower confidence rather than guess.

## Confidence scoring & uncertainty

Two separate numbers, on purpose:
- **`p_ai`** — *which way* the evidence leans (0 = human, 1 = AI).
- **`confidence`** — *how much* to trust that lean (0 = coin flip, 1 = certain).

```
p_ai       = 0.65 * s_llm + 0.35 * s_stylo        # LLM leads (stronger signal)
disagree   = |s_llm - s_stylo|
raw_conf   = 2 * |p_ai - 0.5|                       # distance from the midpoint
confidence = raw_conf * (1 - 0.5 * disagree)        # disagreement halves conf at most
```
(Implemented in [scoring.py](scoring.py).)

**Verdict thresholds — asymmetric on purpose:**

| Verdict | Rule |
|---|---|
| `likely_human` | `p_ai ≤ 0.45` and `confidence ≥ 0.35` |
| `likely_ai` | `p_ai ≥ 0.65` and `confidence ≥ 0.35` |
| `uncertain` | everything else |

Both non-uncertain verdicts need `confidence ≥ 0.35`; the asymmetry lives in
`p_ai`. The AI band starts at `0.65` (well above the 0.5 midpoint) while the
human band reaches to `0.45` — so it takes stronger, *agreeing* evidence to flag
AI than to call something human. This is not a binary flip at 0.5: a 0.51 lands
in the wide "uncertain" band, a 0.95 does not.

### How we tested that scores are meaningful
We ran a fixed set of inputs spanning the range and checked the scores match
intuition. Live results (real Groq LLM):

| Input | stylo | llm | p_ai | verdict |
|---|---|---|---|---|
| Casual human (ramen review) | 0.31 | 0.2 | 0.24 | **likely_human** |
| Uniform/templated AI | 0.59 | 0.8 | 0.73 | **likely_ai** |
| Rich-vocab AI (essay) | 0.41 | 0.7 | 0.59 | uncertain |
| Formal human (economics) | 0.52 | 0.7 | 0.64 | uncertain |

Clearly-AI (`p_ai` 0.73) is well separated from clearly-human (`p_ai` 0.24), and
all three verdicts are reachable. The two "uncertain" rows are the design
working: the LLM leans AI but stylometry disagrees (rich-vocab essay) or `p_ai`
stays just under 0.65 (formal human) — so the system declines to accuse rather
than risk a false positive. The scoring is also unit-tested against a
worked-examples table in [planning.md](planning.md) §2 (`SPEC TABLE == CODE`).

## Transparency label

The label returned to the reader **changes with the verdict and confidence** —
the confidence percentage and band word (HIGH / MODERATE / LOW) are interpolated,
so the same text is never shown regardless of score. AI wording is hedged and
never accusatory. Exact text of all three variants
(`{pct}` = `round(confidence*100)`, `{band}` = HIGH/MODERATE/LOW):

**Variant A — AI-leaning (`likely_ai`):**
> ⚠️ Likely AI-generated. Our automated analysis found signs this text may have been produced with AI assistance (confidence: {pct}% — {band}). This is an estimate, not a certainty, and it is not an accusation. If you're the creator and this is wrong, you can appeal and a human will review it.

**Variant B — Human-leaning (`likely_human`):**
> ✓ Likely human-written. Our automated analysis found signs this text was written by a person (confidence: {pct}% — {band}). This is an automated estimate, not a guarantee of authorship.

**Variant C — Uncertain (`uncertain`):**
> ❔ Attribution uncertain. Our automated analysis couldn't confidently determine whether this text was written by a person or generated with AI (confidence: {pct}% — {band}). Please treat the origin as inconclusive. No attribution claim is being made.

Example rendered output (live), one per variant:

```
[likely_ai / 40%]   ⚠️ Likely AI-generated. ... (confidence: 40% — MODERATE). ...
[likely_human/50%]  ✓ Likely human-written. ... (confidence: 50% — MODERATE). ...
[uncertain / 15%]   ❔ Attribution uncertain. ... (confidence: 15% — LOW). ...
```
(Implemented in [labels.py](labels.py).)

## Appeals workflow

A creator who disagrees with a classification can contest it. An appeal captures
the creator's reasoning, logs it **alongside** the original decision (nothing is
overwritten), and flips the content's status to `under_review`. Automated
re-classification is intentionally not done — a human reviewer resolves it.

```bash
curl -s -X POST http://localhost:5000/appeal \
  -H "Content-Type: application/json" \
  -d '{"content_id": "c_40d66e576f13", "creator_reasoning": "I wrote this myself. English is my second language, so my writing can read as formulaic."}'
```
Response:
```json
{
  "appeal_id": "a_97bc3f4cbbdf",
  "content_id": "c_40d66e576f13",
  "status": "under_review",
  "message": "Your appeal has been logged and this content is now under human review."
}
```
The appeal then appears in `GET /log` (with `status: under_review` and the
`appeal_reasoning` populated) and in the reviewer queue at `GET /appeals`, which
shows each under-review item with the creator's reasoning and the original
decision (both signal scores) side by side. Unknown `content_id` → `404`.

## Rate limiting

Applied to `POST /submit` via Flask-Limiter (per client IP, in-memory storage):

| Limit | Value |
|---|---|
| Per minute | **10** |
| Per day | **100** |

**Reasoning.** These are keyed to realistic behavior on a writing platform, not
arbitrary:
- **10/minute** — a real creator submits their own work occasionally, not in
  bursts. Even someone actively checking several drafts won't exceed ~10 in a
  minute. Anything above that is a script, so the per-minute cap is the primary
  defense against a flood. It's also the layer that protects cost: each submit
  makes a paid Groq LLM call, and rate limiting runs *before* detection, so
  rejected requests cost nothing.
- **100/day** — bounds a single client's total daily LLM spend and catches a
  slow-drip abuser who stays under 10/min but hammers the endpoint all day
  (would hit 14,400/day unchecked). 100 is comfortably above any legitimate
  individual creator's daily volume.

Exceeding a limit returns `429` with a JSON body:
```json
{ "error": "rate limit exceeded", "limit": "10 per minute;100 per day", "detail": "10 per 1 minute" }
```

**Evidence** — 12 rapid requests against a fresh server (first 10 pass, rest are
rejected):
```
req 1 -> 200      req 5 -> 200      req 9  -> 200
req 2 -> 200      req 6 -> 200      req 10 -> 200
req 3 -> 200      req 7 -> 200      req 11 -> 429
req 4 -> 200      req 8 -> 200      req 12 -> 429
```

entry records: timestamp, content id, creator id, attribution, confidence (+
band), `p_ai`, signal agreement, scoring mode, **both individual signal scores**
(with the stylometric sub-metrics and the LLM rationale), and status. An
**appeal** entry records the appeal id, reasoning, `under_review` status, and a
snapshot of the original decision.

## Graceful degradation

If the Groq key is missing or the API call fails, `llm_score` returns `null` with
an error, and the pipeline falls back to the stylometric signal alone with
confidence capped into the LOW band — so degraded mode always returns
**uncertain**. Without the semantic signal the system makes no confident
attribution claim in either direction, and the failure is recorded in the log.

## Anticipated edge cases

- **Minimalist / repetitive human poetry** — stylometry flags it AI-like, but the
  LLM reads it as human; the disagreement drives the verdict to *uncertain*, not
  a false AI accusation.
- **Very short text (< ~25 words)** — stylometric statistics are unstable; the
  signal is flagged and confidence is capped LOW.
- **Non-native-English human writing** — the LLM can over-flag formal non-native
  prose; the `p_ai ≥ 0.65` bar plus the appeal path limit the harm (this is the
  exact scenario in the sample appeal above).
- **Human-edited AI drafts** — genuinely mixed provenance; these correctly land
  in *uncertain*.
